## 1. Context
Two documents defined conflicting rules: Blueprint v1.0 (governance authority)
and Master Guide (product detail). Blueprint §1 states it supersedes older documents on conflict. This ODR records explicit resolutions for all conflicts.

## 2. Conflicts and Resolutions

### C1 — Market Classification / Stock Group Hierarchy
- Blueprint: SECTOR → SUB-SECTOR → STOCK GROUP → STOCK (Stock Group in hierarchy)
- Guide: SECTOR → SUB-SECTOR → STOCK; Master Stock Group as separate registry
- **RESOLVED:** Guide model adopted. Stock Group is a *separate registry*, not
a Market Classification hierarchy level. However, Stock Group remains a
Rotation aggregation level (RAW → STOCK GROUP → SUB-SECTOR → SECTOR).
- **Status:** OWNER_APPROVED

### C2 — Theme Hierarchy
- Blueprint: THEME → SUB-THEME → INDUSTRY → COMPANY → STOCK
- Guide: THEME → SUB-THEME → INDUSTRY → STOCK
- **RESOLVED:** Guide model adopted. COMPANY is not a Theme hierarchy level.
Value Chain remains a separate Stock 360°/Business layer, never a Theme level.
- **Status:** OWNER_APPROVED

### C3 — Confidence Gates
- Blueprint: Minimum Aggregation Confidence Threshold = 60%
- Guide: CONF_MIN = 30
- **RESOLVED:** TWO DISTINCT GATES exist with different purposes:
  - CONF_MIN = 30 → Stock Group Rotation **inclusion/publication gate**
  - 60% → **higher-level aggregation/roll-up eligibility gate**
  - Confidence is an inclusion gate only. Never multiplies Rotation Score.
- **Status:** OWNER_APPROVED

### C4 — Rotation Weights Mutability
- Blueprint: 40/30/20/10 configurable subject to validation
- Guide: Locked
- **RESOLVED:** 40/30/20/10 is the protected Revision 3 baseline. Admin
configuration is possible ONLY as validated, explicitly versioned
configuration. No silent live edits. Every changed weight-set produces a new
formula version + audit snapshot. Calculation proceeds from the versioned
configuration.
- **Status:** OWNER_APPROVED

### C5 — Canonical Data Status Vocabulary
- Blueprint (8): LIVE, DELAYED, STALE, UNAVAILABLE, MISSING, UNKNOWN, PENDING, VERIFIED
- Guide: LIVE, DELAYED, STALE, MISSING, NOT_INTERPRETABLE, SOURCE_REQUIRED, UNKNOWN
- **RESOLVED:** Status architecture separates four semantic dimensions:
  - Freshness/Availability: LIVE, DELAYED, STALE, UNAVAILABLE
  - Verification: VERIFIED, UNKNOWN
  - Interpretation: NOT_INTERPRETABLE
  - Workflow: SOURCE_REQUIRED, PENDING, MISSING
  Missing is never zero. Each dimension has its own enum in the schema.
- **Status:** OWNER_APPROVED

### C6 — D2 Flat State
- **RESOLVED:** Approved. If all valid capped returns are zero:
  - State = FLAT
  - Default 40/30/20/10 weights → mathematical score = 40
  - Custom valid weights → normal weighted formula applies; do NOT force 40
  - Tests mandatory for both default and custom weight cases
- **Status:** OWNER_APPROVED

### C7 — Value Chain Data Contract
- **RESOLVED:** Master Guide's rich dimensions adopted. Value Chain includes:
raw material/input, mining/extraction (where applicable), sourcing,
processing, manufacturing, capacity/utilisation/capex, products/by-products,
customers/distribution, downstream, final end-use.
Every relationship must be evidence-backed. Value Chain does NOT become a
hierarchy level.
- **Status:** OWNER_APPROVED

### C8 — Governance Status Registry
- **RESOLVED:** Mandatory. Four distinct statuses tracked separately:
  1. Document status
  2. Rule/formula status
  3. Implementation status
  4. Runtime status
  "Document Approved" ≠ "Code Implemented" ≠ "Runtime PASS."
- **Status:** OWNER_APPROVED

### C9 — Role Model
- **RESOLVED:** 3-tier model approved: OWNER → ADMIN → USER.
  Admin can perform operational authority but CANNOT:
  - Block/delete/disable/revoke Owner
  - Bypass MFA
  - Create/grant authority
  - Change locked formulas
  - Modify/delete audit history
- **Status:** OWNER_APPROVED

### C10 — Management Guidance Mapping
- **RESOLVED:** Positive = 80, Neutral = 50, Negative = 20 approved as the
documented Growth/Visibility scoring lookup.
Additional bonus/weight/aggregation is NOT invented. Management Guidance is
used only within the existing SS-1.0-R3 Growth/Visibility formula contract.
Exact % weight within SS-1.0-R3 remains as documented; no change without
further evidence.
- **Status:** OWNER_APPROVED
