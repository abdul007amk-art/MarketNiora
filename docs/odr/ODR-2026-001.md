## 1. Context
Blueprint v1.0 §16 stated: "Normal user signup uses server validation and secure
password hashing." This implied password-based authentication. Product intent
confirmed by Owner (2026-09-20) is OIDC-only for user login, with Owner requiring
additional TOTP MFA.

## 2. Options Considered
- A — Password-only (as written in §16): REJECTED
- B — Google OAuth (OIDC) for users + Google OAuth + TOTP for Owner: **ADOPTED**
- C — Hybrid OAuth + password fallback: REJECTED

## 3. Decision (Recorded)
1. User login = Google OAuth (OIDC) ONLY. Server verifies ID token via Google
   JWKS (`aud`, `iss`, `exp`, `sub`, `email_verified`). No user password stored.
2. Owner login = Google OAuth (OIDC) + MANDATORY TOTP MFA. Owner role is
   server-controlled via `OWNER_EMAILS` whitelist; no public Owner signup.
3. `User.role` default = `user`. Client cannot set role or elevate.
4. Owner without confirmed TOTP secret → login BLOCKED (fail-closed).
5. Client cannot set `role`, `entitlement.tier`, `isVerified`, `MFA_verified`,
   or any payment flag (Blueprint §15, §16).

## 4. Rationale
- Eliminates password hash storage and credential-stuffing attack surface.
- OIDC ID tokens cryptographically verifiable server-side (zero-trust, §11).
- Industry-standard UX.
- Owner security strictly stronger than users (mandatory TOTP).

- §14: Unchanged — Owner MFA mandatory.
